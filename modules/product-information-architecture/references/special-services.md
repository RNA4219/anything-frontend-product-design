# 窓口・手続き・資料の版

各指示はDRAFT。ID先に原典・依存・失敗例・適用限界がある。

| 場面・ルール | 指示と例外 | 確かめ方 |
|---|---|---|
| [210](../../../registry/A/skills/A-IU-210.json) 複数組織にまたがるサービスの境界や問い合わせ先が曖昧なとき | サービスの責任主体と連絡先を入口・終端で示し、共通のヘルプは同じ位置に置く。手段ごとの対応範囲を明記する。 設計システムの政府公式マークは利用資格があるサイトだけに使う。 | 代表的な相談を1件選び、入口・エラー・完了から担当窓口と利用条件に到達できるか試す。 |
| [211](../../../registry/A/skills/A-IU-211.json) 利用可能な人や必要書類が決まった長い手続き | 開始ページに利用条件、準備物、見込み時間、代替窓口を置き、対象外と判明した人に適切な行き先を示す。 複雑な適格性を確定できない場合は予備判定と明示する。 | 対象者と非対象者の2例で開始前の判断と、必要な書類が不足したときの行動を確認する。 |
| [212](../../../registry/A/skills/A-IU-212.json) 複数のタスクを順不同または順番に終える申請 | 先に必要な作業だけを前提として示す。手順一覧、タスク状態、現在の段階を分けて表記する。 少数の直線的ステップでは、タスク一覧を別に作る負担も比較する。 | 1件を未完了にしたまま別タスクへ進み、本当にその前提が必要か、表示と実際の挙動を照合する。 |
| [213](../../../registry/A/skills/A-IU-213.json) 更新日やファイル形式が利用判断に影響する長期公開資料 | 内容をいつ点検したかを示し、PDFや映像には利用可能な形式と対応する範囲を示す。本文を更新したら代替版も照合する。 サイト共通のフッターの年だけから、個別文書の確認日を推定しない。 | 古い資料と現行資料を用意し、更新日はどちらの内容を指すか、別形式で必要な判断を再現できるかを試す。 |
