# 入力修正と確定前の判断

この手順はB-IU-005/006を実行する。原典の要件・推奨と、状態管理へ適用する推論を区別する。

## B-IU-005 — 直せる箇所から再開する

まず観測を分類する。

| 観測 | 保持するもの | 次の経路 |
| --- | --- | --- |
| 確定した入力拒否 | 通常の入力は正しい値も誤った値も保持 | 該当項目、テキスト説明、安全に示せる修正案、再検証 |
| 入力で直せないサービス・権限等の問題 | 有効な下書きと参照情報 | 実際に利用できる復帰・案内。無関係な項目にエラーを付けない |
| 応答喪失で結果未確認 | 送信内容と操作ID | B-IU-001/002の照合。入力ミスや送信不成立と決めない |

1. 自動検出した問題の項目と理由をテキストで特定する。
2. 修正案が分かる場合は示す。セキュリティや内容の目的を損なう修正案の例外は、項目の識別・エラー説明すべてを免除するものではない。
3. 修正対象だけを編集できるようにし、関係ない有効な入力を失わせない。誤入力も比較して直せるように保持する。秘密情報の表示・保存は具体的契約で決める。
4. 修正後に必要な検証を行い、残る問題と解消した問題を分ける。クライアントの下書き保持はサーバーへの保存完了ではない。

WCAG 2.2の3.3.1/3.3.3は自動検出エラーの識別・説明と既知の修正案を扱う。
正常値と誤入力値の保持はGOV.UKの設計ガイドに基づく適用方針であり、3.3.1に同じ文章があるという主張ではない。
[WCAG 2.2](https://www.w3.org/TR/WCAG22/#input-assistance) ·
[GOV.UK Error message](https://design-system.service.gov.uk/components/error-message/)

同一プロセスで既入力・既提示の情報を再び求めるなら、3.3.7に従い、自動入力または選択手段を備える。
再入力が本質的、セキュリティに必要、以前の情報が無効、という3例外を項目ごとに確認する。
個人情報という一語で全項目の再入力を正当化せず、この要件だけで無期限・セッション間保存も要求しない。
[Understanding 3.3.7](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry)

## B-IU-006 — 確認した内容と確定する内容を一致させる

誤操作防止の手段を先に選ぶ。WCAG 3.3.4(AA)の対象は、法的約束・金融取引・保存システム内の
ユーザーが制御するデータの変更/削除・テスト回答の送信など、規範で列挙された操作である。
対象を不可逆操作だけに縮めない。可逆、入力検査と修正機会、確定前の見直し・確認・修正のうち
少なくとも一つを成立させる。毎操作のモーダルや3手段すべてを要求する規則にしない。
可逆性を選ぶ場合は[B-IU-004](undo-and-compensation.md)で実効性を確かめる。
[規範3.3.4](https://www.w3.org/TR/WCAG22/#error-prevention-legal-financial-data) ·
[解説（informative）](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data)

確認を選んだタスクでは次を実行する。

1. 最終的に提出・変更する有効な内容と、その操作の効果を示す。確認表示や変更リンク自体では提出しない。
2. 項目を変更する際は既入力を渡す。変更によって必要になった追加質問を済ませ、確認へ戻る。
3. 変更で無効になった確認・見積・同意等の範囲を仕様から決める。無関係な回答を消さず、関係ない画面をすべて通り直させない。
4. 最終送信には、利用者が最後に確認した有効な内容を使う。確認後に有効内容が変わったら再確認へ戻す。
5. 分岐から外れた古い回答は、下書きに保持できる場合でも有効な送信内容へ黙って含めない。非該当になった質問のエラーも現在の確定条件から外す。有効な他項目のエラーは保持し、質問が再び必要になれば再検証する。

例：配送を店頭受取へ変更したら住所の再入力は不要。住所を下書きに残すことと、今回の申請へ送ることは別である。
再び配送を選んだ場合は住所の現在の有効性を確認する。依存判断の失効や送信内容の分離は、このCampaignの適用上の推論である。
[GOV.UK Check answers](https://design-system.service.gov.uk/patterns/check-answers/)

旧Windows 7向けの確認ガイドは、頻繁な確認への反例を探すための歴史的参考とした。
数値例やボタン表記を現在の普遍規則へ転用していない。
[旧ガイド](https://learn.microsoft.com/en-us/windows/win32/uxguide/mess-confirm)
