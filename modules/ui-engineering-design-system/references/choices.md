# 候補・タブ・キー操作

入口の共通手順を踏み、該当する項目を使う。リンク先に入力、成果、失敗例、検証状態と原典がある。

## 検索付きの候補リストを実装する場合 [C-UI-201](../../../registry/C/skills/C-UI-201.json)

入力値、キーボードで注目している候補、確定した値を別に持つ。離脱やEscapeで何を保持するかを決める。 候補を矢印で移動してEscape、Enter、Tabで抜け、表示値と提出値を各経路で確認する。

例外・適用条件: 短い固定リストでは標準の選択部品やラジオボタンも比較する。

## 左右キーでタブを切り替える部品を実装するとき [C-UI-202](../../../registry/C/skills/C-UI-202.json)

パネルの表示が即時なら自動選択を比較できる。読込待ちがある場合はフォーカス移動と選択操作を分け、対応するパネル名を結ぶ。 遅延したタブを連続で通過し、現在のタブ・選択済みタブ・表示パネルが矛盾しないか確認する。

例外・適用条件: 別ページへのリンクを見かけだけでタブに変えない。

## 文字キーだけで操作を起動するアプリ [C-UI-203](../../../registry/C/skills/C-UI-203.json)

入力欄と音声入力で意図しない起動が起きないよう、対象フォーカスに限定するか、変更・無効化できるようにする。通常の操作経路も示す。 入力欄に同じ文字を入力し、ショートカットが発火しないことと、設定変更後の代替操作を試す。 メニューから割当キーを発見できるかも観察する。

例外・適用条件: 修飾キーを組み合わせる操作と文字キー単独の操作の適用条件を区別する。
