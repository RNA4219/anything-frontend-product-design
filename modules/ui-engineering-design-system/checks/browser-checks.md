# ブラウザ確認

契約検査とNodeの関数テストはブラウザ合格の代わりにならない。対象ブラウザ、版、OS、入力機器、AT、ズーム、試作ハッシュ、観測日時を記録する。

通常のローカル開発環境でリポジトリをHTTP配信して `examples/booking-controls.html` を開く。外部サービスへの送信はない。

1. buttonをpointer、Enter、Spaceで別々に起動する。一操作につき確定は一回。非送信buttonでform submitが発生しない。
2. 候補未選択と実行不可チェック状態で確定を試す。理由をキーボードでも読め、実行回数は増えない。
3. FormDataにはreadonlyのbookingIdが入り、disabledのarchivedは入らない。読み取り専用checkboxへ変更する反例も別に試す。
4. modalを開く。初期対象は日時欄。Tab/Shift+Tabで背景のpage要素へ漏れない。Escapeと取消ボタンの各経路で閉じ、元の予約を保つ。
5. modal内の境界条件で起動元を削除して閉じる。背景が利用でき、予約見出しがfocusを受ける。focus復帰と背景復旧を別の確認として記録する。
6. 非モーダル案内を開き、背景のメモへ移動する。外側からcloseした場合にメモのfocusを奪わない。
7. 確定→再表示→Escapeで、古いreturnValueが新たな確定を起こさない。

AT確認では名前・役割・状態・変化の通知と、読み上げで操作を完了できるかを記録する。DOMや自動チェッカーだけで発話成功やWCAG全適合を記録しない。
