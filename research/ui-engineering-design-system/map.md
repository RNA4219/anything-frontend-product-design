# UI実装・デザインシステムの原典地図

**問い**　既存部品の再利用と新設判断、ネイティブ部品、セマンティクス・キーボード・通知、状態の契約、トークンと変更影響を、予約変更の実装と検証でどう結び付けるか。

| 論点 | 採用資料 | 支える判断 |
| --- | --- | --- |
| 知見はどの媒体に集まり、何を判断できるか | GOV-1・HTML-1・WCAG-1 | システムの採用基準は制作者、要素の仕様はWHATWG、検証条件はW3Cから読む |
| どんなとき既存部品で足りず、どんな証拠が共有部品化を支えるか | GOV-1・GOV-2 | サービス固有の合成と複数利用面を持つ共通部品を見分け、既存用途と更新影響を比べる |
| 単一選択、フォーカス、通知の原典は何で、標準のまま成立しない条件は何か | HTML-1・HTML-2・ARIA-1・WCAG-1・WAI-1・WAI-2 | radioを使う条件と、領域の切り替え・継続状態の通知を使い分ける条件 |
| 競合と送信結果不明をどの条件で区別し、何を照合すれば再送できるか | STR-1・STR-2 | サーバー契約が定める処理の同一性・照合範囲を確認する |
| 値を差し替えたとき、どの利用箇所をどう追い直すか | USW-1・DTCG-1 | 用途名から依存箇所と対になる値を調べる |

用語と媒体は [調査ログ](log.md)、版・箇所・原文取得は [原典台帳](sources.md) を参照。実装への採用条件は [担当Skill](../../modules/ui-engineering-design-system/SKILL.md) に置く。
