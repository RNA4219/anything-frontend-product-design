## 操作数の読み方

- 1件は「ブランド・施設 × 用件 × 端末条件」。同じ対象を別の用件で調べた場合、ブランド総数では1件とした。候補探しでトップを開いただけのサイトは表に含めていない。
- PCは1365 × 900 CSS pxのマウス操作、スマホは390 × 844 CSS pxのタッチ操作。いずれもMicrosoft Edge 158の自動ブラウザーを使い、スマホ幅はPixel 7相当の設定を用いた。各試行は未ログインの新しいセッションで開始した。地域別の入口は各行の開始URLに残した。
- クリックとタップには、検索欄へのフォーカスや規約の展開も含む。文字列を欄に入れる操作を入力1回、Enterでの送信をキー1回とした。初期URLへの移動、ブラウザーの自動スクロール、本文の読み取りは回数に含めていない。初期画面内かどうかは、測定できた答えの表示位置で判定した。スワイプ数、探す時間、利用者の視線は未計測。
- 再試行した枠では、条件と答えを照合できた経路を1本掲載した。未確認は停止地点を併記した。表示制限や自動操作が完了しなかった試行も含む。検索の0件が発生しなかった2件は前提不成立とした。ここでの件数は観察できた経路数であり、人の成功率やサイトの順位は測っていない。
- 商品詳細から戻る補助試験は往路の操作数に含めていない。ハンズPC幅とIKEA日本スマホ幅では、商品一覧に戻った際に検索欄の値を確認できた。ロフトのスマホ幅では一覧本文に語が残り、検索欄内では値を確認できなかった。日時・順序・到達URLは[観察データ](observations.json)からたどれる。

## 利用者を観察した一次調査との照合

今回の自動操作では、どの操作が難しかったかを人に尋ねていない。次の4資料では調査実施者が参加者の様子や設計変更を報告している。

- Baymardの決済調査では、2024年の平均が5.1ステップ、11.3入力欄だった。画面の移動数と、利用者が検討・入力する欄を別々に測る根拠になる。[調査本文](https://baymard.com/research-articles/checkout-flow-average-form-fields)
- Baymardが報告したSephoraの一参加者は、検索語を入れた後に虫眼鏡を繰り返しタップし、約40秒後にキーボードの送信操作を見つけた。今回の検索試行ではEnterで送信できることまでを確かめた。初めて来た人が送信方法を見つけられるかは、別に観察する必要がある。[調査本文](https://baymard.com/research-articles/mobile-search-submit-button)
- 英国教育省は教員養成課程を探す候補者10人に、絞り込み・並べ替えの試作を使ってもらった。スマホ8人、PC2人。先行調査で見つかった「条件を適用・解除しにくい」「何が選択中か分かりにくい」という問題を、明示的な観察項目にしている。[調査本文](https://becoming-a-teacher.design-history.education.gov.uk/find-teacher-training/filtering-and-sorting-ur/)
- GOV.UK Verifyでは利用者名とパスワードを別ページで試した後、両方の用語を一緒に説明した方が理解しやすい参加者に合わせ、同じページに戻した。ページをまとめる判断には、入力の手間と説明の理解の両方が関わる。[調査本文](https://userresearch.blog.gov.uk/2015/08/13/no-more-accordions-how-to-choose-a-form-structure/)
