## 測った範囲と読み方

- **端末条件と操作。** Edgeの新しいブラウザーセッションで、PC幅は1365×900 CSS px、スマホ幅は390×844 CSS pxのタッチ操作を使った。クリック・タップ、文字入力、キー入力、記録したスクロールは別々に数えた。入力欄のフォーカスを押した場合も1回とした。要素を画面に収める自動スクロールや、同じ目的で行った再試行は操作列にすべては含まれない。スクロール位置は撮影時のページ上端からの距離で、指のスワイプ数や総移動距離は測っていない。

- **判定。** 終点確認は用件の答えを実画面で特定できた場合。途中まではサイトを操作できたものの、最後の画面で必要な条件を確認できなかった場合。入口を利用できなかった条件は表示不可、誤記で商品が返るなど課題が想定する状態が発生しなかった条件は前提不成立とした。ログイン、個人情報の入力、注文、再設定メールの送信は行っていない。件数は今回確認できた経路を表す。利用者の成功率やサイト間の優劣については、この調査からは判断できない。

- **情報密度。** 画面に収まった操作要素の個数と、文字列を囲む矩形の面積率を示す。折り返した行は別の文字断片になる。重なる矩形の面積は一度だけ数え、操作要素や文字の親要素について、画面内にある部分の中心が別の要素で隠れていれば集計から外した。この方法では一部だけの遮蔽を誤判定することがある。JSONには操作要素・画像等の矩形面積率、重なりを除いた合計、10万平方CSS px当たりの操作要素数も収録した。文字の矩形面積率は文字のインク面積、情報の価値、読解時間を表さない。

- **余白の距離。** 各画面の中央50%幅に、文字・操作要素・画像・CSS背景画像の矩形がかからず、RGB各成分の最大値と最小値の差が8以下となる最長の連続領域を探し、縦の長さをCSS pxで記録した。均一な黒や有色の背景も含む。JSONの上端は領域に含み、下端は含まない。見出しや期限の数字と説明文については、対応を確認できた例で矩形間の縦距離も掲載した。0 pxなら両者の矩形が接している。

- **対象となる画面。** 入口と終点が同じ表示のときは、両方の記録に同じ画面が含まれる。途中で止まった経路でも、表示できた商品一覧やヘルプは計測した。同意画面が前面にある場合はその状態を明記し、アクセス制限、ブラウザーのエラー、読み込み表示や空画面の余白・密度は欠測とした。価格・時刻・条件は観察時の地域向け表示に従っている。
