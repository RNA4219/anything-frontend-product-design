# 製品評価チェックリスト

## 測る前に決める

| 実施 | 測定前に決めること |
| --- | --- |
| [ ] | 対象の版・役割・用件ID・受入条件ID・初期データ・端末幅・入力方法・終点と確認する事実を記す。低頻度でも失敗の影響が大きい用件を含める。[情報設計](../modules/product-information-architecture/SKILL.md) |
| [ ] | 正常・失敗直後・復帰後から試す条件を選び、適用外には理由を記す。目的達成やデータ損失、影響を受ける人、回避策から必須／参考を決め、必須を外すときは根拠と判断者を残す。[操作フロー](../modules/interaction-ux-flow/SKILL.md) |
| [ ] | 必須条件の合格基準と根拠を、仕様・利用者への約束・既存版との比較などから決める。基準未定の値は参考測定とし、他社のタップ数や余白をそのまま合格値にしない。 |

## 用件ごとに点検する

次の表から用件に該当する項目を選び、用件ID・端末・入力方法ごとに測って、実施チェックと合否を分けて記す。

| 実施 | 項目 | 測る値・確認する条件 |
| --- | --- | --- |
| [ ] | 目的達成 | 正しい対象と結果を確認した試行数／実行試行数。終点で答え・確定状態を照合する。 |
| [ ] | 操作の手数 | クリック／タップ、入力、確定キー、戻るの各回数。同意や案内を閉じた操作も含め、未完了時は停止位置を残す。 |
| [ ] | 答えの位置 | 初期画面内か、読めた位置のスクロール量（CSS px）。判断に必要な対象と答えが同時に見えるか確認し、ダイアログ内の移動はページと分ける。 |
| [ ] | 要素間の余白 | 関連する二要素の端間距離（CSS px）と測定点・方向。画面中央50%幅を横切り、検出要素と交差しない均一色の連続領域の最長の縦の長さは別欄にする。[測定の定義](../research/product-journeys/spacing/README.md) |
| [ ] | 情報密度 | 画面内の操作要素数と文字の矩形面積率（%）。入口と終点を同じ幅・高さで測り、画面内のテキスト断片（折り返しごと）の矩形の和集合面積を表示面積で割って100を掛ける。同意画面などの重なりも記録する。 |
| [ ] | 操作と復帰 | 指定した入力方法で完了できた条件数と修正の操作数。エラー後の表示、保持した入力、次に操作できる場所を確認する。[部品の操作条件](../modules/ui-engineering-design-system/SKILL.md) |
| [ ] | 更新の正しさ | 確定件数・重複件数・再表示後の値。更新のある用件で確定前後・再試行後の正本を照合し、競合や応答消失を扱うなら変更前の状態も記す。 |

探しやすさを評価する場合は参加者の正答人数／試行人数・所要時間・支援の有無を別に記録し、自動操作の成功件数と人の達成率を分ける。[測定の定義と用件別の実例](site-comparisons.md)

| 実施 | 判定 |

| [ ] | 実測が基準に合えば合格、操作が効かないなど基準違反を観察したら不合格。必要な観測値や証拠が足りなければ証拠不足、環境などで手順を実行できなければ未実施とし、理由を記す。欠測は0にしない。 |
