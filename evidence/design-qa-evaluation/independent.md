# 独立評価と修正後の再試行

評価者には、工作室の予約変更について正常、競合、応答消失を同じ課題で比較し、キーボードでの操作と公開までの残条件を調べる依頼を渡した。参照資料は担当 Skill、共通課題、予約変更の評価手順、ブラウザー上の A・B。評価者には実装コード、実装者の所見、採用案の期待解を渡さなかった。

## 初回の発見

Edge 158.0.4370.33、1280×900 CSS px、ポインターとキーボード、追加操作を含む15試行・88観測。試作 SHA-256 は `709a2c431b2873fd9a48dc390df0a852c2b6e0a7354e54c5abf9db8d410b6f61`。

- A、Bとも正常は12月10日・1回。競合後は12月8日・0回、別枠の12月11日に復帰後は1回。Aの通知からは競合の理由や対処が読み取れなかった。
- Aは応答消失後、「もう一度確定してください」に従って再送すると12月10日・2回。Bは照会で12月10日・1回、同じ枠の再送後も1回。
- Bで照会前に「R-204 の日時を変更」を押すと、応答消失の案内が消えた。一覧は12月8日のまま、確認画面は12月10日から12月10日への変更と表示し、同じ予約を異なる日時で示した。
- 受入計画に通知直後のフォーカスと照会前の再編集可否を加え、手順に直後再表示の別試行を追加した。試作では照会前の再編集を止め、旧日時を確認中として表示し、同じ日時の再送には変更がないことを知らせるよう修正した。

## 再試行
